## 产物形态

- `npm run build` 输出静态站点到 `dist/`。
- `vite.config.ts` 使用 `base: '/'`，站点必须挂在域名根路径。
- 站点页面（`/`、`/people`、`/events`、`/timeline` 等）由前端根据 `location.pathname` 渲染；年表内部深链使用 URL hash（如 `#han/wudi`、`#military/event/xianyang-zhi-zhan`）。
- 静态托管只直接返回 `index.html`。未知路径由 `public/404.html` 载入 `public/404.js`，重定向到 `/?path=...`，再由前端还原 `history` 路径。`/404.js` 是独立文件，不能改回内联脚本，否则会被 CSP 的 `script-src 'self'` 拦截。
- 运行时不读取环境变量，没有服务端组件、数据库、定时任务或第三方 API。页面只请求同源 `/data/*.json`；图片全部来自 `public/media/` 与 `public/images/`；导出使用 canvas `toBlob` 与本地 `blob:` 下载。
- 页面不加载外部字体或第三方脚本。`font-family` 只使用系统字体。

## 复现与本地验证

1. 确认 Node.js 22 或更高版本。
2. 安装依赖。

   ```bash
   npm ci
   ```

3. 运行门禁。

   ```bash
   npm test
   npm run format:check
   npm run build
   ```

4. 确认产物包含 `_headers`。

   ```bash
   ls dist/_headers
   ```

5. 用能实际应用 `_headers` 的服务器打开生产产物。

   ```bash
   npx wrangler pages dev dist
   ```

   `npm run preview` 与 `vite preview` 不会读取 `_headers`，不能用来验证响应头。

6. 抽查响应头。

   ```bash
   curl -sI http://127.0.0.1:8788/ | sed -n '1,20p'
   curl -sI http://127.0.0.1:8788/index.html | sed -n '1,20p'
   curl -sI http://127.0.0.1:8788/data/index.json | sed -n '1,20p'
   ```

   带 hash 的 `/assets/*` 需替换为 `dist/assets/` 下的真实文件名。

7. 用浏览器检查首页与 `/timeline`：控制台无 CSP violation，年表 canvas 非空，PNG 导出仍触发本地下载。

## 主路径：Cloudflare Pages

### 仓库内配置

- `public/_headers` 定义响应头。Vite 构建时把 `public/` 复制到 `dist/`，Cloudflare Pages 读取 `dist/_headers`。
- 构建命令为 `npm run build`，输出目录为 `dist`，Node 版本使用环境变量 `NODE_VERSION=22`。
- 仓库不包含 Cloudflare 部署 workflow，也不保存任何 Cloudflare token 或账号 ID。当前现网是直接上传 `dist/`。若以后改为 GitHub Actions 部署，`CLOUDFLARE_API_TOKEN` 或 `CLOUDFLARE_ACCOUNT_ID` 缺失时 workflow 必须跳过并成功退出，不能让 CI 变红。

### 已完成的发布

项目 `lantai` 用直接上传发布当前 `dist/`，没有连接 Git。自定义域名、DNS 和响应头已经在线上生效。下一次内容更新在提交推送之前，继续用直接上传，不要改成从 `main` 构建。

接到 Git 之后的构建设置：Build command `npm run build`，Output directory `dist`，`NODE_VERSION=22`。

### 响应头策略

`public/_headers` 的规则：

| 路径 | Cache-Control | 说明 |
|---|---|---|
| `/*` | 不设置 | `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: strict-origin-when-cross-origin`、`Strict-Transport-Security: max-age=31536000`、`Content-Security-Policy` |
| `/assets/*` | `public, max-age=31536000, immutable` | 文件名带内容哈希 |
| `/data/*` | `public, max-age=0, must-revalidate` | 文件名固定，内容随发布变化，不能长缓存 |
| `/`、`/index.html` | `no-cache` | 入口必须及时更新 |

CSP 策略：

```text
default-src 'self';
script-src 'self';
style-src 'self' 'unsafe-inline';
img-src 'self' data: blob:;
font-src 'self';
connect-src 'self';
object-src 'none';
base-uri 'self';
frame-ancestors 'none';
form-action 'self'
```

- `script-src` 保持 `'self'`，不加入 `'unsafe-inline'`。`404.html` 的内联重定向脚本已拆到 `/404.js`。
- `style-src` 需要 `'unsafe-inline'`：卡片、目录和年表泳道通过内联 `style` 属性传入运行时配色。
- `img-src` 允许 `data:` 与 `blob:`，覆盖潜在的 canvas 图像与本地导出预览；当前页面图片全部同源。
- `font-src` 只需要 `'self'`；页面没有远程字体。
- `connect-src` 只需要 `'self'`；运行时只请求同源 `/data/*.json`。
- HSTS 使用一年，不添加 `preload` 或 `includeSubDomains`，避免把尚未验证的子域一起锁定。

### 部署后验证

- `curl -sI https://lantai.0xenzyme.dev/`：HTML 返回 `Cache-Control: no-cache`，并带完整安全头。
- `curl -sI https://lantai.0xenzyme.dev/assets/<hash>.js`：返回 `public, max-age=31536000, immutable`。
- `curl -sI https://lantai.0xenzyme.dev/data/index.json`：返回 `public, max-age=0, must-revalidate`。
- 浏览器打开 `/`、`/timeline` 与一个详情深链，确认控制台没有 CSP violation，年表 canvas 非空，PNG 导出可用。
- securityheaders.com 评分不低于 B。
