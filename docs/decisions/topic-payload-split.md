# 专题载荷只承载年表，不承载传记正文

## 决定

`public/data/<topic>.json` 的 `people[]` 不再包含 `bio`。年表首屏只下发布局与卡片摘要所需的字段：身份、生卒、称号、泳道、标签、分类、政权、性别。

传记正文仍只保存在 `public/data/people/<id>.json`。年表人物卡打开时，由 `src/app/model.ts` 的 `ensurePersonBio` 按 id 读取详情，补入卡片“简介”一栏；结果按人物 id 缓存，同一人物重复打开不重复请求。

## 理由

汉专题升级到 45 人时，专题载荷中的首段传记合计已约占该文件 gzip 体积的一半。首包上限为 200KB（压缩后），继续按每批 5 人、每人 700 字以上推进，会在数批内触顶。

年表首屏并不渲染人物卡；卡片只在用户点选后出现。因此把传记正文放进首包属于重复承载：同一段正文在 `people/<id>.json` 中已经存在。

## 影响

- 首包（`index.json` + `timeline-people.json` + `timeline-events.json` + 默认专题）体积下降，后续专题扩充不再线性抬高首包。
- 打开人物卡时多一次按 id 的详情请求；请求失败时卡片其余字段仍可用，简介显示“传记尚未整理”。
- 站点页面（`src/site/`）不受影响：人物页、群像页与全站搜索读取的是 `people.json` 与 `people/<id>.json`。
- 机器闸门：`tests/pipeline.test.ts` 断言专题载荷不得含 `bio`。

## 未拆分的内容

`relations` 与 `views` 留在专题载荷内：关系聚焦与章节按钮都依赖同步布局，拆分需要改动同步渲染路径，收益小于传记正文。事件完整记录亦保留，因为 `views[].events` 的运行期校验以它为准。
